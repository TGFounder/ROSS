# ROSS v1.2.0 candidate (Efficiency Engine): review package

Status: **CANDIDATE — AWAITING INDEPENDENT REVIEW AND FOUNDER ACCEPTANCE.**
Branch `candidate/ross-efficiency-engine`, started from `4497770`. Not merged,
tagged or released. `v1.0.0` (5e54f13) untouched.

## Starting evidence (candidate 1)

Matched result: about 3.3% fewer tokens, 52% fewer shell/test executions,
39% more turns, protections never triggered, no semantic state recorded.

## Architecture

One canonical runtime (`runtime/ross.py`, standard library, no network
imports) with thin host packaging generated by `distribution/build.py`.

Preserved from candidate 1: local state store, delta writes, same-session
duplicate-read refusal, test reuse on identical inputs, repeated-failure
guard, secret redaction, inspect/forget, transcript usage, packaging and drift
check.

New in this build:

- **Automatic memory (A).** `UserPromptSubmit` takes the goal from a coding
  prompt; `Stop` keeps the last 500 characters of the agent's final message
  and any explicit `Next:` line (`last_assistant_message`, no model call);
  changed files, git state and test results are derived. No `ross note`
  turns; the kernel no longer asks the agent to maintain state.
- **Context injection.** Nothing at `SessionStart`. On the first resume or
  coding prompt of a session, one block: resume state (only if a previous
  session exists) plus a repo symbol map (Python AST, lexical for others;
  index stores hashes and symbol names, never file content).
- **Tool-output compression (B).** Heavy commands are rewritten through
  `PreToolUse` `updatedInput` to `ross.py exec`, which runs the original
  command unchanged, preserves its exit code, stores full output in a
  bounded (64 MB), redacted, content-addressed artifact store, and prints only
  actionable lines (test failures and summaries, compiler errors, tracebacks,
  diff file lists and hunks, generic error lines plus head and tail).
  Outputs under 3,000 characters pass through. `ross artifact ID --grep X`
  retrieves anything.
- **File context (C).** A same-session reread of a changed file returns a
  unified diff against the earlier version read from git's object store (no
  copies kept); whole-file reads over 60 KB return an outline plus the first
  150 lines.
- **Turn economy (D).** No ROSS-induced turns; kernel rule to batch
  independent reads, searches and commands.
- **Telemetry v2.** `savings` labels MEASURED (provider usage), COUNTED,
  ESTIMATED (bytes/4).
- **Kernel.** About 525 body tokens (candidate 1: about 600; v1.0.0: about
  1,440 total).

## Host findings (Claude Code 2.1.286)

- `PostToolUse` `updatedToolOutput` was emitted correctly but **not applied**
  to Bash results; the model saw raw output. Output compression therefore
  uses `PreToolUse` `updatedInput`, which **is applied** (verified live).
- Claude Code already persists very large outputs (about 30 KB+) to a file and
  shows a 2 KB preview; in a live probe that cost an extra turn when the key
  line was outside the preview. ROSS's exec wrapper avoids that for wrapped
  commands.
- About 90% of tokens are cache reads of the host's own per-turn prefix. ROSS
  cannot modify that prefix; it can only reduce turns and what enters context.

## Failed experiments and limits

- `updatedToolOutput` compression path: not applied by the host (above).
- Workload 3 (about 30 interactions): not reached. Sonnet finished Session A
  in 3 to 5 turns; the workload was not lengthened artificially.
- Workload 6 (changed large file): agents read files through shell commands,
  not the Read tool, so diff-on-reread never fired live; covered by unit test
  only.
- Session B was near its floor (2.3 turns average against a minimum of 2),
  limiting further resume savings on this workload.

## Regressions

- Short-task overhead measured above the 2% gate (see above).
- Candidate 1 bug fixed: `git()` stripped the first status line, truncating a
  path; `__pycache__` leaked into changed files.

## Privacy

Local only; no network, telemetry, accounts or extra models. New stored data:
goal text (≤400 chars), last result (≤500 chars), symbol names, and large
command outputs in `.ross/artifacts/` (redacted, capped, prunable). No
conversations or source copies. `forget --project` / `--everything` delete all.

## OpenAI

Packages generated from the same canonical files; static checks pass against
current OpenAI plugin docs (root `plugin.json`, `skills/`, `hooks/hooks.json`,
`CLAUDE_PLUGIN_ROOT` compatibility). Codex `updatedInput` and output handling
are unverified. **OPENAI LIVE ECONOMICS TEST PENDING AUTHORIZATION.**

## Largest remaining waste source

Host per-turn prefix replay (about 90% of tokens), outside ROSS's control.
The controllable levers left are turn count and the size of what enters
context; on short, efficient sessions both are already near their floor.
